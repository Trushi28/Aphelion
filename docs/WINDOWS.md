# Windows executor

Aphelion is not POSIX and does not try to be. Running Windows programs is a separate layer: a clean-room executor that loads PE images and answers their calls with Aphelion's own primitives. It is built in stages, and each stage is host-tested before anything runs in ring 3.

Licence rule for this layer: ReactOS, Wine, Sogen and NeptuneOS are behaviour references only. Their source is not read and no code is copied. Documented behaviour (Microsoft's published PE format and API contracts) and observation of real binaries are the inputs.

## W1: the PE loader (`kernel/include/cosmos/pe.hpp`)

A pure header with no kernel dependencies, namespace `pe`. It never allocates. The kernel, a host tool and the tests all use the same code.

| Function | What it does |
| --- | --- |
| `parse(file, size, &image)` | Validates every header, section and directory the loader will later touch and fills an `Image` (about 8 KiB, fits on a stack). On any failure the image is zeroed. |
| `plan(image, runs, cap)` | Merged page runs: headers read-only, each section at its own protection, gaps read-only. Returns the full count even when `cap` is smaller. |
| `map(image, file, size, buffer, bytes)` | Copies headers and section data into a zeroed flat image buffer of `size_of_image` bytes. |
| `relocate(image, buffer, base, &applied)` | Applies DIR64, HIGHLOW and ABSOLUTE relocations for a 64 KiB-aligned base. |
| `bind_imports(image, buffer, resolver, ctx, &report)` | Resolves every import by name or ordinal. Two passes: nothing is written to the IAT unless everything resolved. |
| `tls_info(image, buffer, base, &tls)` | Template, zero fill, index slot and callback list, as absolute addresses for the stated base. |

### What is accepted

- PE32+ for x86-64 only. PE32 and i386 return `Pe32Unsupported`; a CLR directory returns `ManagedUnsupported`.
- Section alignment a power of two from 4096 to 1 MiB and at least the file alignment; file alignment a power of two from 512 to 65536.
- At most 96 sections and 16 MiB of image. The preferred base must be 64 KiB aligned and below the user limit.
- Section addresses ascending and aligned; raw data aligned, inside the file, outside the headers and non-overlapping.
- Every directory (except Security, which is a file offset) lies inside one section or the headers.
- The entry point is inside an executable section. A DLL may have none.

### What is refused, on purpose

- A section that is both writable and executable (`WritableExecutable`). Windows allows it and some packers rely on it; Aphelion keeps W^X unconditional.
- Relocation entries that touch the headers, gaps, or cross the end of a section.
- Relocation-stripped images at any base other than the preferred one (`NeedsFixedBase`).
- A TLS callback outside executable memory.

### Missing imports

`bind_imports` returns `UnresolvedImport` and fills an `ImportReport`: counts of libraries, imports, resolved and missing, plus the first 32 missing entries with DLL name and function name or ordinal. The loader refuses to run the program and names the function, rather than starting it and crashing later through a null import slot. The resolver is called once per import in each pass.

### Tests

`make test-pe` builds `tools/pe_host_test.cpp` with ASan and UBSan. It contains:

- a synthetic PE builder (four sections, imports, TLS, exceptions, relocations), about fifty directed malformed-header cases that each check the exact status, and a second builder for the limits (section count, alignments, image size, the user-limit boundary);
- 4000 random section layouts checked against an independent invariant function and an independent page-plan checker;
- every truncation of the sample images, byte-value sweeps over every header byte, table sweeps over the import, TLS and relocation tables with an exact-size image so ASan sees any overrun, and 300,000 random multi-field header rewrites;
- four real images linked by `lld-link` (`tools/pe-samples/`, regenerated by `build.sh`, embedded as base64 in `tools/pe_samples.hpp`): a console program with TLS and a pointer table, the same program fixed-base, a program importing by name and by ordinal from an import library, and a DLL.

Mutation check: 348 single-token mutants of `pe.hpp` (comparison operators, `&&` and `||`, `+` and `-`, and every early `return Status::X` replaced by `Ok`) were run against the suite under ASan and UBSan with `-fno-sanitize-recover=undefined`. 323 are killed. The other 25 are equivalent: the changed bound is guarded by another check (for example `size <= 64` in `parse`, where a 64-byte file fails the PE offset check anyway), the array past `directory_count` is always zero, or the changed value only affects an empty copy. The first round of the check found gaps at the exact limits (96 sections, 255-character names, 256 libraries, 32767 imports, 16 TLS callbacks, 33 missing imports, empty relocation blocks, a plan into a short buffer) and a real bug: `plan` read past a short output array when merging runs. Each now has a directed test.

A differential run against `pefile` on lld output (default alignment, `/align:65536 /filealign:4096`, `/filealign:1024`) agreed on image base, entry, sizes, section table, protections, imports and relocation counts. That check is not part of `make test-pe`, because it needs Python and `pefile`.

### Limits

- Nothing in the kernel includes `pe.hpp` yet. W1 is the parser and loader logic only; W2 is the first user.
- Exports, forwarders, delay imports, bound imports, resources, the load config directory and exception unwinding data are validated for position only. W5 reads exports when DLLs are loaded.
- 32-bit PE files are refused, not emulated.
- The samples are produced by one linker (lld). Binaries from MSVC, MinGW or packers have more variety; the sweeps cover malformed input, not every legitimate layout.
